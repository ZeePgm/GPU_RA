# V3 三条只读路径恢复验收

最终源码 A 为 `0722355b9e7e6f1e0a62e3555af67aa94583f576`。RTX 5070 上的四组正确性简测均通过。[构建、入口与权重范围](../../experiments/v3-restore-r2-001/README.md)

| 最终运行 | 核对结果 |
|---|---|
| [第二次 F 原入口](second-f-20261118-002.md) | F1 生成一个 token。原驱动先用原生计算采集 GPU 分段表，再用该表推进 S3Gate 的时钟。三个 6 MiB 矩阵各一个主机父读取，合计 4,608 个 Global、294,912 个 64 B fragment。原 F 验收器确认完整 logits 匹配、每个消费者在门控之后派发、每 token 的计算与等待时间逐 ps 守恒、主机和设备排空。 |
| [选定权重 symbolic](symbolic-20261118-002.md) | 同一个 TensorAccessBridge 和在线审计处理新权重尺寸。6 MiB down 整矩阵一个父请求；embedding 真实第 32 行一次 2,048 B 读取，32 个 64 B fragment。扩展模型入口对 norm 的每次实际消费读取 4,096 B，初始化预留为 32,768 B。 |
| [R2 PTX](ptx-20261118-003.md) | 模型通过 ggml 的 MUL 算术 hook 执行原 R2 norm PTX。44 个 prefill 行加 3 个 decode 行，每行 1,024 次 4 B 请求，共 48,128 次。独立 down 第 0 行的 3,072 宽度夹具经过两次调用，与原 CPU FMA/归约参考逐位匹配。将完整 down 送入模型 norm 入口会显式拒绝。 |
| [V3 B2 CUDA](cuda-20261118-002.md) | 6 MiB down 执行 24 次读核、12,288 个 512 B 请求、393,216 次 lane 检查，所有块完成后一次 D2D 发布。2,048 B embedding 行也只发布一次。保留 B2 读核、warp 补充策略、整次发布以及借用权重完整性检查。 |

三种选定入口分别使用 Qwen3-0.6B F16、44-token 提示、4 个输出、native KV，在完整模型中只选第 10 层 ffn_norm。每个进程的四步完整 logits、token、KV 序列化字节、位置与释放结果均匹配 `reference-20261117-001`。组件另外对相应权重的原生输出逐位核对。此次没有运行五权重正式性能矩阵，未评估速度排名或新权重的联合模拟时钟。

初版 A 为 `a42440b03e93dc177072f78ffd54964af250a054`。PTX 首次登记在原资源守卫处因沙箱无法枚举系统进程而退出。具备主机可见性的运行通过。选定 symbolic 的首版小 norm 初始化遇到无可推进事件：历史 H0 的块组与新清单的稀疏注册边界不匹配。最终版对扩展入口采用清单对应的 V3 块组几何，初始化写满注册预留，每次消费仍按真实有效字节读取。独立第二次 F 入口继续使用原 H0 配置。两次失败均封存；两个源码提交的运行分别登记。

原 99 个进程对应 `dd4ee95d` 的 sampled 候选。该报告中的性能结果仅适用于当时的实现。10 个候选读者、注册、适配和专属测试文件已从当前 V3 移除。历史代码可在封存提交检出，原报告、清单、seals 及外部运行文件保留。
