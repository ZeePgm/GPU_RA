# A组实验设计：时钟、调度与工作量独立验证

日期：2026-11-02；状态：设计，尚未实施或验收。

## 1. 目的与范围

A1 检查同步 gate 处注入的真实等待如何影响 token 墙钟，同时独立验证模拟时钟记账；A2 在受控机制配置下对拍事件调度；A3 独立预测 H0 请求拆分和工作量，再考察尺寸对模拟延迟的影响。三项均无需新硬件；A1 使用现有 GPU，A2/A3 可使用后端及测试环境。

这些实验不能单独证明完整 HBF 架构正确、参数准确或真实硬件性能。现有 S 系列基础和限制见 [S0—S9报告](GPU_S0_S9_EXPERIMENT_REPORT.md)、[S8结果](GPU_S8_RESULTS.md)及[S6限定验收](GPU_S6_MINIMUM_ACCEPTANCE.md)。原交接文档的时间契约见[第6—7节](../third_party/HBF-EventLab/docs/gpu_experiment_handoff.md)。

## 2. A1：延迟注入与独立时钟对照

### 2.1 问题与执行路径

在 S8 的消费者前同步 gate 加入实验注入模式：前序 GPU 工作完成后、选中消费者发射前进行阻塞；不提交 HBF 访问。使用相同 gate ID、输入、GPU 执行方式和输出边界，比较真实等待对 token 交付的影响和模拟时钟对预设等待的记账。[现有门控](../experiments/gpu_s/hbf_gate.hpp)、[S8同步与执行条件](GPU_S8_RESULTS.md)。

| 模式 | 真实 gate 行为 | 模拟记账 | 用途 |
|---|---|---|---|
| zero | 相同打点及门控路径，等待为零 | 零等待 | 墙钟及模拟基线 |
| inject | 按表忙等待，记录开始和结束的单调墙钟 | 不将实际墙钟耗时回填模拟 tick | 真实时间效应 |
| model | 不进行真实注入，使用同一注入表 | 逐点推进预设 W | 模拟时间检查 |

所有模式必须验证消费者在门控结束后提交；相同 ID、顺序及 token 行为。各模式的日志开销应尽量一致，测量与核验模式分别说明。忙等待使用单调高分辨率时钟；先单独测量其分辨率、超调和调度扰动，不能假定 sleep 精确。

### 2.2 两个独立时钟的合同

模拟时钟：对每个 gate 记录预设整数 ps 的 W_j。对 token i，model 与 zero 的模拟相对时刻差必须精确等于该 token 之前的 ΣW_j，逐 token 整数残差为零。预设计算轨迹和门控顺序一致；对错序、缺失或身份不符的表明确拒绝。

墙钟：使用同一单调时钟分别记录请求开始、每次注入起止和 token ID 可交付时刻。第 j 次实际注入为 Ŵ_j = end_j − start_j；逐 token 比较配对差 T_i(inject) − T_i(zero) 与该 token 前的 ΣŴ_j，并记录每次 Ŵ_j − W_j 的注入器误差。墙钟噪声、调度与记录开销不得当作模拟时间；模拟时钟也不是墙钟测量的真值。

两项独立判定：模拟精确一致不自动构成墙钟通过；墙钟效果可见也不能替代模拟残差检查。输出逐项 pass/fail/inconclusive 和原因。

### 2.3 矩阵和统计

以 S8 的 Qwen3-0.6B、44-token 输入、8输出和 M2 gate 身份为起点。单点仅在首 token 前指定 gate 注入；多点在16个预登记 gate 注入。候选每点 W 为 0、10、100、1000 µs；这些是机制测试量级，不代表 HBF 延迟。先验证足够量程、计时精度及实际 gate 数；不支持的点标记不适用。

先预热并进行独立试运行，以配对差波动决定正式样本量和可检测范围。正式阶段每条件至少30组配对，配对顺序随机或平衡；冻结同一进程/上下文复用策略及随机种子。记录系统和 GPU 状态，预先登记样本中断、失败与排除规则。试运行后、正式采样前冻结对每个量级的等效界限、置信区间方法及最大样本预算；无法达到精度的量级标为 inconclusive，不调整界限以迎合结果。

报告逐 token 的配对差中位数、分布、95%置信区间、预设及实际注入总时长，以及 ITL/TTFT/TPOT 对应差值。墙钟通过要求：预先定义的效应误差置信区间全部落在冻结的等效界限内；未达到精度且不能排除界限时为 inconclusive。不同 token 和多个条件的检验与多重比较规则在正式采样前冻结。

### 2.4 负控与限制

在某 token 交付之后的 gate 注入，预期不改变该 token 的此前时刻；注入表错序、缺点或 gate ID 不符须被拒绝。保留失败数据，不混入正常性能样本。核验 token、输出数量、gate/消费者因果顺序和无额外预测步。

该实验验证当前串行同步点的因果传播和两套计时契约，不验证 HBF 服务时间、NAND 搬运、异步重叠或所有系统架构。CXLMemSim 对未修改应用使用监测及延迟模拟，可作为相关背景，但本实验直接修改 gate，方法不同：[CXLMemSim原论文](https://arxiv.org/abs/2303.06153)。SC-W’23 FPGA 具体论文尚未核实，不作为验收依据。

## 3. A2：受控机制配置与解析对拍

本项**不是完整 H0 验证**。先建立或配置可证明满足单服务台、FIFO、非抢占、整数 tick、无重试和无其他竞争资源的机制案例。检查现有执行引擎是否能真实表达这些条件；若不能，则只对独立微型机制实现报告结果，不能宣称验证了现有 H0。

对每个到达时刻 a_i 和服务时间 s_i，独立参考计算 b_i=max(a_i,c_(i−1))、c_i=b_i+s_i，初始服务台空闲；等待为 b_i−a_i。参考实现只读取测试输入及明确的同 tick 仲裁规则，不读取引擎结果生成期望。

覆盖单请求、空闲间隔、同时到达、连续积压、可变服务时长、恰在完成 tick 到达，以及零/非法值边界；规定合法服务时间和 tie-break。以整数 ps 逐项对比到达、服务开始、完成、等待及顺序，要求精确一致。错序、重复、漏完成、错误时长负控应被独立比较器拒绝。

可选 M/G/1：仅在机制配置满足泊松到达、独立同分布服务、FIFO 单服务台及 ρ=λE[S]<1 时，对照 E[Wq]=λE[S²]/(2(1−ρ))。候选负载 0.2、0.5、0.8；冻结随机种子、预热、独立批次、置信区间、误差要求和最大预算。有限样本精度不足标 inconclusive。不得将该公式当成复杂 H0 的直接预言。

输出条件、逐请求轨迹、参考结果、残差、负控、统计方法和结果。若要验证完整 H0，需另设独立参考，覆盖其实际资源、拆分、并行与调度规则。

## 4. A3：独立工作量计数与尺寸响应

### 4.1 基线与尺寸

固定 H0 参数、单 channel、单次仅一个读，固定地址策略、内容身份和初始化；每个点以相同初始状态的新 Session 执行，初始化不计入请求延迟。先从实际配置及实现识别 64B、页、Global 等边界与合法对齐规则，再冻结尺寸矩阵。对每个相关边界 B 测试合法的前、上、后点，例如 B−64、B、B+64，再补充小、中、大点，总计至少6个不同尺寸；不合法点标注而非强行执行。边界仅作候选，须由实现核实。

每点至少运行三次验证确定性；如果配置含随机性，固定或记录种子，明确统计口径。另设地址对齐和并发度的单因素扩展，不能混进基线拟合。

### 4.2 独立计数合同

独立审计器只读取冻结的请求地址、长度、区域清单及明确的映射/拆分规则，计算预期有效交集、64B片段及地址、Global 数量和边界归属；不得读取后端输出计数生成期望，也不得调用被测拆分实现。将预测逐项对比原始桥、Global 和片段事件，再对比汇总统计。保留可复算的输入、预期与实际记录。

对事件副本注入缺片、重复、错误地址和边界归属错误等负控，要求审计拒绝。只有独立计数、身份、成功及排空检查全部通过的点才能进入响应分析；失败点保留并标识，不删除或静默修复。

### 4.3 响应分析

每点记录有效字节、独立预测和实际计数、关键命令、提交/完成 tick、等待及资源状态。先根据配置和实现规则冻结候选断点及预测模型，再报告每点误差；预留未参与拟合的尺寸检验预测。不得预设一定分段线性：拆分、取整、资源并行及调度可能产生台阶或其他响应。

确定性模型的拟合残差范围不等于硬件测量误差；只有随机采样具有合适的独立重复时才报告统计置信区间。结果限定于指定 H0 配置与工作量，不证明参数符合真实硬件。

## 5. 交付和阶段判定

建议顺序：A2确定性机制对拍 → A1注入 → A3尺寸扫描。每项建立独立批次，保存源码和二进制身份、配置、输入及哈希、环境、原始事件、独立参考/审计、分析脚本、负控、结果表和判定；记录中断及未完成项。脚本不得覆盖旧批次。A1报告两套时钟的单独判定，A2报告机制配置而非 H0，A3先报告独立计数再报告响应。

本设计不预填结果。实施前须冻结 A1统计等效界、A2机制配置及 tie-break、A3实际边界和独立拆分规则；条件不可建立时记录阻断或 inconclusive，不能以预期替代实测。
