# 只读接入与 KV 优化并行实验设计

日期为 2026-11-07。本文是待执行方案，依据当前源代码、架构说明和已有实验记录设计。所有性能结论均需由新实验产生。

## 1. 范围与决策

主模型采用 Qwen3-0.6B，使用当前受支持的 F16 模型、固定 llama.cpp 和后端构建。第一阶段保留计算算子、精度和后端配置，分别改变只读接入或 KV 管理。Qwen3-1.7B 和 SmolLM2-135M 用作后续模型留出验证。

只读线依次解决统一接入、同算子双路径对照和覆盖扩展。KV 线依次解决数据搬运、写回放大、多序列集成、事务取消及异步分页。每项实验独立判定，已通过的前置实验才进入下一阶段。

这里的完整适配有三个层次，结果必须注明层次。

1. 当前选定范围内，每次应捕获的读取全部捕获。
2. 一个目标算子的所有指定权重行、层和合法形状得到支持。
3. 模型全部声明为 HBF 管理的只读权重都有经过验证的接入路径。

第三级需要先列出 embedding、attention、FFN、norm、输出层等实际张量与算子清单，再逐项适配。实验通过的覆盖集合按字节、张量、算子、层分别报告。

## 3. 共用验收规则

### 3.1 正确性与数值

对地址覆盖、请求身份、版本、引用计数、整数模拟时间及真实页字节使用独立 oracle，要求预期和实际完全一致。依据是这些对象具有确定的离散语义，缺失一次、重复一次或读取错误版本都会破坏执行合同。

oracle 从输入张量形状、访问计划、事务脚本计算预期值，不调用被测实现的范围合并、拆分或版本生成函数。多种合法调度下，核对因果偏序和结果，只有固定到达、策略和事件次序的确定性夹具才要求完整时间线一致。

保持计算顺序和算术实现的同路径 timing/bypass 对照，要求 logits 数组精确相等，沿用 run_llama_integrated.py 中的现有合同。真实 KV 存储、换页和回读要求字节相等。若宣称逐位一致，另外比较原始数组字节，不能只使用数值相等判断。

对独立 native 数值参考，复用模型 profile 和现有验证器的冻结容差及 token 条件，在实验 manifest 中保存阈值和来源。核验工具见 [run_llama_integrated.py](../tools/run_llama_integrated.py) 和 [integrated_profile.py](../tools/integrated_profile.py)。改变归约或精度的优化需另立数值合同，在正式采样前论证并冻结，不能根据候选结果放宽旧阈值。

### 3.2 机制、性能与合入分别判定

- 功能通过要求全部声明范围的正例、边界例与负例满足合同。
- 机制通过要求独立计算的请求数、传输字节、快照数或依赖关系与实际一致，且目标限制在指定用例中得到解除。
- 性能获益要求独立确认样本支持事先声明的主指标改善。功能通过而区间过宽时，性能标为 inconclusive。
- 默认启用还需要满足事先确定的适用范围及退化预算。范围外可继续采用原策略，选择规则必须在留出验证前冻结。

没有统一的“提速 5%”或“误差 10%”门槛。内存上限来自配置预算，数量预期来自访问/事务计划，数值容差来自已有合同，性能收益界来自具体决策成本。

### 3.3 P0 测量资格与采样方案

P0 是两条工作线共用的准备工作。

1. 冻结源码、构建、模型/profile、驱动、配置、输入 token、随机种子、采集开关和后端策略。当前工作区有未提交改动，因此同时保存相关文件哈希。
2. 在代表性短/长 prefill 与 decode 上运行 A/A 配对先导，检查顺序效应、漂移和采集开销。冷加载/编译与稳态分别采样。正确性审计和低扰动性能采样分开，保存两个构建/开关的对应关系。
3. 独立进程或完整会话作为统计单位。一个进程内的 token 和多个 kernel 视作相关观测，不当作独立重复。随机化并平衡 A/B 顺序，保存热状态和时钟等可取得的环境记录。
4. 每个实验只设一个主性能终点，例如完整 decode 阶段的墙钟时间；GPU 阶段时间、CPU 服务时间、模拟完成时间和字节数作为分解指标。测量端点必须在协议中明确，禁止跨时钟域直接相减。
5. 推荐确认阶段使用按独立会话分组的配对置信区间，总体错误声明预算设为 0.05。这个数是预先选择的统计决策风险约定，不是实现常数。多个主条件同时作结论时使用预声明的 Holm 调整或同时置信区间。样本太少时采用适当的参数/随机化方法或保留不确定性，不能默认 bootstrap 会自动可靠。
6. 先导估计方差和漂移后，按目标最小效应 δ_min 规划样本量。δ_min 优先来自是否改变策略选择的交叉点、额外初始化成本摊销或已明确的延迟预算。若没有可论证的 δ_min，只报告效应区间，实验保持探索性质，不设臆造的收益门槛。
7. 正式采样前固定样本量、最大运行预算和失效样本处理规则。δ_min 的检测能力目标也要在协议中声明并说明误判成本。预算不足以达到精度时标记 inconclusive，不追加到显著为止。A/A 的区间必须足够窄、能支持目标分辨率；区间包含零本身不足以取得测量资格。
8. 以旧减新时间为收益 D，正值表示改善。仅声称“存在改善”时，调整后区间下界需大于零；声称“具有决策价值”时，下界需超过 δ_min。等效或非劣结论要有事先论证的界，未检出差异不能自动判定等效。

历史 A1 的样本数和噪声范围只作为风险线索，新入口需重新做 P0。以上风险预算为建议协议参数，正式实验冻结时记录采用值及理由。

### 3.4 用例从结构边界推导

设页大小 P=4096 B、sector 大小 S=64 B、token block 长度 B、ubatch 长度 U。用例覆盖 B−1/B/B+1、U−1/U/U+1，行字节数覆盖小于页、跨页及大于页，访问范围覆盖 sector/DLU 边界、非连续范围和尾部有效 lane。

模型用例仅使用其合法形状，特殊边界由合成算子/事务夹具覆盖。页框配置覆盖最低合法预算、刚好容纳指定工作集、比工作集少一个页框及充足预算；先用独立页面计划验证能否触发预定事件，避免选择无法运行的配置。

所有失败路径检查无成功结果伪造、无提前发布、无重复完成。可恢复故障检查规定的回收状态；严重会话失效按错误合同终止并保存仍占用的资源诊断。

## 4. 只读线实验

### R1 统一只读接入模块，保持原有行为

**突破限制**：norm/down 的注册、生命周期、覆盖检查和日志分散在不同适配器中，新算子接入需要重复实现管理代码。

**实现方案**：建立统一的 tensor/选区注册、接入策略选择、请求身份与审计接口。保留 PTX 和显式 CUDA 实现以及当前请求粒度。共享 LiveTimingService 和错误处理，入口明确报告选中的策略和支持形状。统一模块不承担 GPU 页框或 Host 命令调度。

**实验与对照**：同一模型和选择范围，新旧管理实现分别执行 native/bypass/modeled；每一种原接入策略单独配对。加入重复注册、越界、错误角色、生命周期错误、加载失败和最终失败用例。

**验收与理由**：

- 每个逻辑访问的 tensor、offset、bytes、操作类型、父子归属和覆盖多重集一致。重命名后的 ID 用稳定逻辑键对应。依据是重构不改变访问合同。
- 固定到达轨迹的后端回放结果及时间一致；实时 GPU 的到达漂移单独报告。依据是固定输入可确定性比较，真实启动时间允许变化。
- 数值、错误、关闭和排空满足共用合同。注册对象和运行资源的生命周期无泄漏。
- 统一模块能通过两种策略完成相同的生命周期用例。R1 以功能与维护结构验收，性能记录用于发现开销，不要求重构必须提速。

**交付**：共同接口、策略支持表、新旧逻辑轨迹差异报告和回归摘要。通过后冻结接口供两条线使用。

### R2 同一算子的 PTX／显式 CUDA 等价对照

**突破限制**：现有 norm 与 down 使用不同算子和请求粒度，无法据此归因两种接入技术的代价。

**实现方案**：先为同一个 norm 权重乘法增加显式标量入口，再为 down 的同一选定范围增加受支持 PTX 入口。冻结算术表达式、布局、归约、启动形状和访问集合。若 PTX 暂不能表达等价 warp 合并，第一轮让双方采用相同标量请求，再把粒度优化放入 R3。

**实验与对照**：每个算子分别运行未插桩、插桩但绕过计时、完整建模。记录编译/JIT、稳态 GPU、主机服务、mailbox 数、sector 多重集、最终 Global 与数值结果。各路径实际到达时间单独记录，再用固定轨迹回放隔离后端行为。

**验收与理由**：

- 相同选择范围和粒度下，覆盖、请求归属、内容身份与预期一致；丢请求、重复请求和越界均为失败。依据是只有等价工作才能比较接入开销。
- 相同算术合同满足现有数值标准；bypass/modeled 的同路径数值精确相等。若编译结果改变运算顺序，标为新算术变体，先通过独立数值资格再比较。
- 固定输入的后端回放完成结果一致，全部依赖消费者在许可后执行。
- 使用 P0 比较两种入口的主指标，允许结果为各有适用范围或 inconclusive；R2 的验收目标是取得可归因的比较结果，不预定 PTX 或 CUDA 胜出。

**交付**：按算子/形状列出的正确性、开销和实现复杂度表，附实际支持指令及拒绝原因。

### R3 请求合并、覆盖扩展与混合选择

**突破限制**：标量提交可能产生较多 mailbox 工作，当前 down 只覆盖选定行，接入范围难以扩展到更多张量和形状。

**实现方案**：在 R2 之后逐项启用合法的 warp/向量范围合并，保留 active lane、predicate、边界和等待语义。将选择范围从当前行扩到完整目标矩阵、再扩到声明的层集合。建立静态能力表，按算子/布局选择 PTX 或显式入口。模型全部权重的覆盖按清单逐项增加。

**实验与对照**：相同完整访问集合下比较合并开/关和两种策略。包括连续、跨 sector、跨 DLU、尾 warp、分歧 predicate、重复地址及非连续访问。训练选择规则使用一组形状，留出其他形状、上下文和模型验证。

**验收与理由**：

- 独立按实际 lane 访问计算唯一覆盖和覆盖次数。合并后的 sector 并集正确、返回值与 lane 对应正确、所有消费者等待充分。物理请求数允许按已声明规则变化。
- 在对齐且全活跃的 32-lane、每 lane 4 B 夹具中，一个 128 B 合并跨度对应两个 64 B sector，原标量路径通常对应 32 次客户端访问。要求实际数量等于所选合并规则推导值，避免把理论倍数当作墙钟加速倍数。
- 对声明张量和层集合，期望访问全部被捕获，覆盖分母从模型清单独立生成。缺少一项即不能通过该覆盖层级。
- 合并优势用例满足 P0 的性能判断，非连续/低活跃用例报告开销；混合选择规则在留出前冻结。仅对通过条件默认启用。

**交付**：覆盖清单、策略分界、精确请求计数和留出结果。全模型覆盖是逐项里程碑，不以选定算子的通过代替。

## 5. KV 线实验

### K1 GPU 写入容量页，减少可避免的往返搬运

**突破限制**：适配器把新 K/V pack 后下载到主机再 write_layer，后续 GPU 使用时可能重新上传。当前页镜像虽有命中机制，初始化数据路径仍产生潜在重复搬运。

**实现方案**：先建立按事务/页的字节账本，区分 pack 后 D2H、页上传、写租约下载和最终写回。增加面向事务的 GPU 写入接口，将 pack 输出写入已租用容量页，在 CUDA 完成后标记对应层就绪。先保留现有 finish 的安全回收，再单独实验驻留 GPU 脏页权威状态。权威状态必须显式记录，主机读取、淘汰、checkpoint 和失败处理均消费该状态。

**实验与对照**：冻结权重线，比较原路径、安全 GPU 直写路径、可选延迟回收路径。覆盖同页连续追加、跨页、写后立即读、写后淘汰、主机读、flush、文件 checkpoint 与故障。内存和文件 backing 分开报告。

**验收与理由**：

- commit 前长度和公共可见内容符合原事务规则，commit 后真实 K/V 字节与独立数组 oracle 一致。
- 根据逐页版本和传输事件计算最低必要传输，实际字节数与实现策略的预期一致。全新页完整覆盖的受控用例可省去旧内容上传；部分页更新必须保留未覆盖字节，只有证明有效部分已在 GPU 或被完整覆盖时才能免上传。
- 对确有重复往返的夹具，证明指定冗余传输被移除；不存在冗余的用例允许零节省。GPU 总驻留加 staging 必须计入预算，最终下载/flush 计入全生命周期结果。
- 改变字节所有权后必须通过主机读、淘汰及 reopen 字节检查，文件重开以现有 checkpoint 合同为准。
- 性能按 P0 判断。下载次数减少但墙钟不确定时，分别报告机制通过和性能 inconclusive。

### K2 同块脏页合并写回，降低快照放大

**突破限制**：多个脏页逐页写回可能反复生成同一块的完整逻辑快照。

**实现方案**：增加块级脏集合与批量快照提交。选定合并边界时冻结相关数据版本，收集该块所有已初始化页及本批修改，生成一次新内容身份。完成前保护页及版本，成功后按同一提交结果清理对应 dirty 状态。优先在显式 flush 的无并发边界实现，再扩展到受限淘汰。保护同块权重和其他 allocation 的未改字节。

**实验与对照**：在同一块的 m 个页产生多次更新后统一 flush，比较原逐页策略；对照包含 m=1、跨块、部分页、重复更新、权重/KV 同块、夹杂依赖读、有限帧压力和中途 program 失败。

**验收与理由**：

- 无中间可见性屏障的受控用例中，每个脏块生成一个快照。若该块有 q 个已初始化页、原路径触发 m 次独立快照，则预期普通快照页数从 m×q 降为 q。初始化和 Host 故障 replay 分开计数。依据来自现有整块快照合同。
- 存在可见性边界或冲突依赖时按边界拆批，快照数量由独立事务计划推导，不能为了达到一次写回而合并掉必要版本。
- 最终所有页字节、未改权重、块版本及 RAW/WAR/WAW 与串行参考一致。失败时没有尚未完成的页被提前标 clean，已发布数据不能丢失。
- 主机 staging、被保护帧及峰值脏数据不超过显式预算；最低帧配置若不满足批量实现条件，按公布的路径降级并验证回收进展。
- 先验收实际快照工作量下降，再用 P0 检验全生命周期时间收益。只测 flush 前的延迟不足以验收。

### K3 多序列模型集成与隔离

**突破限制**：KvCache 有多序列接口，但模型适配器固定单序列状态。

**实现方案**：将适配器单例 sequence/tx/past/layer 改成按框架 sequence 身份索引的状态。对混合 batch 按 sequence 和位置分组，分别管理 append 和发布。先在单 host owner 下交错多序列，不新增线程共享语义。模型 hook 必须能够传递并校验序列身份。

**实验与对照**：两条序列使用不同 token 和 K/V 模式交错运行，与各自独立运行比较。覆盖异长 prefill、decode、单序列 truncate/reappend、释放后复用槽、容量不足及达到序列配置上限。双序列是证明隔离所需最小规模，再增加到预算边界。

**验收与理由**：

- 每条序列的长度、位置、已提交 K/V 和查询范围与独立 oracle 一致，另一序列的追加/截断/释放不改变它。
- 同算术形状的独立/交错运行满足精确数值合同；混合 batch 改变算术实现时，先按冻结 native 数值合同验收，并用固定 token 轨迹隔离后续传播。
- 逻辑容量、frame、pin、序列数峰值符合配置。全部释放后，业务 allocation 和租约回到启动基线；后端必要历史记录另行记账。
- 一条序列的资源等待不造成永久饥饿。有限请求夹具按明确调度规则得到有界完成；高负载时报告每序列等待分布。
- 本实验以正确多序列集成为主目标，吞吐测量单列，不预设线性扩展收益。

### K4 可取消追加与失败影响范围

**突破限制**：现有 abort/incomplete write 会 poison 整个缓存，限制取消和多序列隔离。

**实现方案**：为未发布追加引入暂存页或 copy-on-write，包括尾块已有页的保护。commit 以一次可见性切换发布页引用和长度，取消在相关 GPU 工作完成或安全终止后回收暂存。应用主动取消、局部可恢复错误与共享介质致命错误分级。先支持安全主动取消，再逐类声明可恢复故障。

**实验与对照**：在分配后、仅 K 完成、部分层完成、全部层完成但未提交、提交点以及淘汰时安排取消/故障。两条序列验证局部影响。重复 abort、重复 commit、旧事务句柄和资源耗尽必须覆盖。

**验收与理由**：

- 发布点之前取消，已提交长度、页字节及版本映射保持原值；暂存资源最终回收。发布点之后的重复操作按明确幂等或拒绝合同处理，不能产生二次发布。
- 同步观察者看到旧状态或完整新状态，不能看见混合层的已提交状态。依据是事务原子可见性。
- 声明可局部恢复的错误不破坏其他序列；共享存储/Session 致命错误维持全局失败传播。每一种可恢复声明都有独立注入用例。
- 额外暂存预算由在途新增页及被复制尾页推导，超预算在破坏旧状态前拒绝或等待。不能靠隐藏无界内存实现取消。
- 报告正常提交的额外拷贝和延迟，通过 P0 判断是否适合默认启用。K4 的核心验收是取消语义和资源闭环。

### K5 有界异步分页与预取计算重叠

**突破限制**：现有 acquire/upload/finish 的同步点和同步预取限制了搬运与计算重叠。

**实现方案**：在 K1 稳定的字节所有权之上，为上传/下载引入独立 CUDA stream、event 依赖和有界 pinned staging 池。租约状态覆盖 preparing/ready/in-use/writeback，发布完成后才允许读取，消费结束后才允许复用页框。预取通过唯一 LiveTimingService 提交，保留外部到达水位和 demand 的进展保证。

**实验与对照**：同步原路径、仅异步搬运、异步搬运加预取三组。包含连续复用、无复用、随机跳转、紧预算、慢介质与到达竞争。先在固定任务 DAG 夹具上核对，再进入模型。

**验收与理由**：

- 每个 GPU 消费者都在对应上传/介质完成后执行，每个页框都在最后消费者结束后复用。按 CUDA 同时钟域事件和独立 DAG 校验，违规次数必须为零。
- GPU 数据、输出、版本、关闭排空满足合同，staging、在途请求和页框始终受预算限制，取消/关闭能够处理所有在途资源。
- 存在重叠机会的夹具中，时间线出现真实独立搬运与计算重叠。固定持续时间的事件模型应与独立 DAG 关键路径整数结果一致；真实 CUDA 用实测区间验证，不能要求零 ps 残差。
- P0 检验主性能终点。随机跳转等退化负例必须报告，并据此冻结预取适用规则，再做留出确认。
- 可选环境维护追加验证 overdue 页数、最长延期、refresh_budget 和租约冲突。若宣称期限满足，必须在事先定义的负载/预算下检查每页期限；刷新次数大于零不足以验收。更广的刷新调度优化另立后续实验。

## 6. J1 联合验收与资源竞争

**突破限制**：两条线单独通过不能确定共享时钟、同块内容和资源竞争下的组合行为。

**实现方案与矩阵**：采用同一基线构建开关形成四组。每项 KV 优化先单独做这组矩阵，再验证最终组合，保留归因能力。

| 组别 | 只读路径 | KV 路径 |
|---|---|---|
| 00 | 原实现 | 原实现 |
| 10 | 新实现 | 原实现 |
| 01 | 原实现 | 新实现 |
| 11 | 新实现 | 新实现 |

初始条件使用单序列以支持四组可比，K3 的多序列在另一组所有版本都能运行的适配器基线上比较。使用短/长 prefill、固定 decode 长度、容量边界与压力用例；长度从 token block、ubatch 和页工作集边界推导。性能实验关闭自动 EOS 提前停止或使用同一固定 token 轨迹，另外验证自然生成的数值/token 合同。

**验收与理由**：

- 四组各自满足声明的语义合同，11 额外覆盖权重/KV 同块、写回期间读、关闭时在途预取和故障。每个实际产生的父请求最终恰好终结一次，需求消费者不能提前执行。
- 共有资源账本能够解释请求数、快照、传输及等待变化。请求合并和写回合并允许后端工作量按计划变化，正确性依靠逻辑内容与依赖 oracle 判断。
- 报告 T00、T10、T01、T11，交互项为 I=T11−T10−T01+T00。按随机化四组会话块估计区间，正 I 表示相对于可加改善存在额外开销。无需要求 I=0，因为共享资源本来会产生交互。
- 联合性能按 P0 判断。若组合退化，则按 CPU 服务、Host admission、Bank、链路、frame/pin 等等待原因定位，再调整策略适用条件并使用新留出数据确认。
- 代表性 Qwen3-1.7B 与 SmolLM2-135M 留出中分别报告覆盖、功能和性能结果，不能用主模型通过替代。

## 7. 并行安排与共享改动归属

| 阶段 | 只读线 | KV 线 | 共同关口 |
|---|---|---|---|
| 准备 | 注册/访问清单、R1 基线 | 传输/快照账本、K1 基线 | P0 与统一请求/统计合同 |
| 第一轮 | R1 → R2 norm | K1 安全 GPU 写入；K3 序列接入可独立准备 | 原模型回归、共享接口冻结 |
| 第二轮 | R2 down → R3 | K2 写回合并；K3 完成集成 | 后端快照与地址/版本评审 |
| 第三轮 | R3 扩大覆盖与留出 | K4 依赖 K3 身份隔离；K5 依赖 K1 所有权稳定 | J1 分项组合、失败与排空 |
| 收尾 | 策略选择冻结 | KV 策略适用范围冻结 | 全组合与留出确认 |

只读线主要拥有 PTX、权重适配和共同只读接口；KV 线拥有 KvCache、CapacityStore、CapacityGpu 和 KV 适配。TimingBackend 的批量快照改动由 K2 单独提交，LiveTimingService 的异步媒介接口由 K5 单独提交。双方在这些接口上使用相同 ID、单位、状态和最终完成定义，避免重复维护两套时钟或调度器。

并行开发使用独立分支/工作目录与独立构建输出，基线和接口变更通过明确版本衔接。GPU 性能采样串行预约，同卡同时运行两条实验会污染对照。
