# 历史实验综述与前端后续工作建议

整理日期：2026-11-04。当前工作基线：E:\v1_update，新后端 8ccb1f3。

本报告依据已有实验报告、协议、结构化摘要及当前接口整理，没有新增性能采样。原文档和历史失败记录保持不变；下述优化方向是基于证据提出的建议，不是已取得的实验结果。来源清单及读取时的 SHA-256 见 [证据索引](validation/experiment-evidence-index-20261104.json)。

## 1. 总体判断

现有工作已经证明：在若干受控模型、访问范围和配置下，真实 GPU 计算、实际字节、符号 HBF 后端、父子请求完成及有限容量能够构成正确闭环。确定性调度、地址/内容核验、故障停止和模拟时间守恒已有较完整证据。

下一阶段的主要缺口是：**测量能否分辨目标效应、覆盖范围是否足够、异步与缓存策略能否在真实执行中带来收益，以及这些结果能否迁移到当前版本和更多工作负载。** 继续增加回归项不能单独补上这些缺口。

必须分开回答四个问题：

| 问题 | 已有证据 | 仍需补齐 |
| --- | --- | --- |
| 功能是否正确 | 数值、真实字节、依赖、版本、关闭排空和负控 | 更多形状、并发、终止和框架生命周期 |
| 容量是否可行 | 历史 4B 分块执行、有限 frame、KV 淘汰回读 | 当前框架路径的全权重有限容量及统一策略 |
| 模拟记账是否自洽 | S5/S8/A1 整数时间守恒、A2 解析对拍、A3 独立计数 | 多资源并发及重叠下的独立关键路径参照 |
| 性能预测是否可信 | 个别算子和受限工作负载的留出检查 | 目标效应检测能力、参数校准、覆盖与泛化；真实 HBF 证据缺失 |

## 3. S 系列：实际 GPU、固定计算轨迹与模拟 token 时间

共同条件：RTX 5070，Qwen3-0.6B F16，单请求/单序列，44-token 输入、最多 8 输出；关闭 graphs/flash attention，显式 F32 矩阵路径。S8 使用 native F16 KV；权重真实字节仍在 GPU，选区通过符号 HBF 访问门控。

| 阶段 | 结果及其可支持范围 |
| --- | --- |
| S0/S1 | 环境、模型身份、指标公式及桥映射；合成 TTFT 35 µs、TPOT 12 µs，真实桥 320 个 64B 片段地址和完成/背压检查通过。合成值不是性能测量 |
| S2/B2 | 旧统一数值合同失败；KV 干预支持舍入反馈是主要传播因素，但干预参照不独立。首次全网络区间候选虽覆盖观测值，却无法证明原精度目标。后来采用分类工程合同，以新 g/h 样本重跑通过；不能改写旧失败或称其为数学误差界 |
| S3/S4 | 单区域、多区域、偏移交集的门控/访问/数值审计通过；S4 两例 H0 等待分别 487788/486121 ps，属于未校准模型值 |
| S5 | 每个非空段人工 1000 ps，每 token 735 个有效段，依赖与整数时间守恒通过；不是实测 GPU 计算成本 |
| S6 | 3 对预热、10 对正式；GPU 活动并集总量中位数 45.696915 ms。较强短段精度要求下仍 inconclusive；后来仅在最小固定轨迹机制目标下限定通过，同一 sample-3 表进入 S7/S8 |
| S7 | 同表零 HBF 等待 G2 回放：TTFT 10.040304 ms、TPOT 5.118493 ms，三次一致；不重新执行 GPU 或 logits |
| S8 | 真实 GPU 与 HBF 同步门控 G3，同表配对；TTFT 增加 0.487788 µs，平均 TPOT 增加 0.267988 µs，第 8 token 累计增加 2.363704 µs；整数守恒残差零 |
| S9 | 三图、覆盖、数值、结束及溯源交付完成；S10 多轨迹/配置敏感性未执行 |

三个关键限制：

1. S8 唯一有效触达 10,240 B、累计读 81,920 B，仅约占模型权重 0.000681%；16 个父读、24 个读 Global、1,280 个 64B 片段成功，不能代表全部模型访存。
2. S6 低插桩请求墙钟中位数约 180.75025 ms，逐段采集约 16,597.165 ms；二者不是硬件 slowdown 比，足以表明当前采集路径扰动很大。GPU 活动并集也不包含完整主机发射间隙，不能改名为请求时延。
3. S8 的 8 输出以长度上限终止，没有该案例的自然 EOS；七个间隔不足以报告可靠 p99。S9 的加载、初始化、后端 CPU 等待、关闭分项墙钟未独立采样，不能由总耗时倒推。

独立 CPU 与 GPU 的旧差异，经 KV 统一干预明显缩小，只支持诊断归因。分类 B2 的通过保护的是指定工程预算；bypass/modeled 同路径逐位一致与独立 CPU 容差通过是两种证据，不能互相替代。

## 4. A 系列：三个独立问题，三种不同结论

### A1：等待注入与墙钟可辨识性

正式协议为单点/多点×10/100/1000 µs，每条件 30 对、共 180 对；每轮新进程/模型/上下文。model 模拟记账、gate 顺序、logits 和因果检查通过，但 **48 个正式统计终点全部 inconclusive，±10% 墙钟定量等效未建立**。

多点累计目标 16 ms 时，墙钟配对差均值 16.936087 ms、中位数 22.097150 ms；相对实际累计等待的平均残差约 0.935 ms，调整后区间约 [−8.984, 10.854] ms，未落在 ±1.6 ms。不同执行顺序的均值也存在约 7.226 ms 差异。点估计接近目标不能代替区间验收。

小剂量末 token 的区间半宽约 8.587–15.081 ms；这是本轮方法的检测精度尺度，不是已排除真实效应的上界，也不是 steady_clock 的时间戳分辨率。

补充单对 full-CUPTI 中，16 个 gate 窗口无 GPU 活动，后置消费者在 gate 后启动；Δgate 合计约 15.9975 ms，但完整 GPU 空隙 Δgap 为 27.757962 ms，包含 pre/post 变化。不能把局部门内事实推广为总体 token 墙钟等效。独立注入器准确度校准尚未完成。

来源：[A1 正式修订报告](GPU_A1_RESULTS.md)、[初始试运行](GPU_A1_PILOT_RESULTS.md)。

### A2：EventQueue 驱动的 FIFO 机制

938 个案例、15,058 个请求、45,174 条单次审计记录与独立标量递推完全一致，最大残差 0 ps；重复结果逐字节一致，负例及同 tick/取消/预算行为检查通过。

被测对象是生产 EventQueue 加实验单服务台 FIFO 适配器，**没有 HostDriver、DeviceDriver 或 H0**。它不能证明 H0 等待或硬件参数正确；可选 M/G/1 统计扩展未执行。[A2 来源](GPU_A2_RESULTS.md)。

### A3：完整 H0 路径的工作量审计与尺寸响应

固定 H0、单 channel、单父读、每次新 Session、相同 64 KiB 普通写初始化；26 点×3 次＝78 会话通过。独立预测有效交集、Global、64B 地址/归属，六类记录篡改均被拒绝。19 个训练点、5 个留出点和 2 个地址子例；留出相对误差均通过 5% 工程目标。

已测主尺寸为 64–32,832 B。五段拟合的斜率/截距实际相同，没有观察到候选边界的折点。事后整数归纳为 T_ps＝110534＋1667×(有效字节/64)，主尺寸整数残差零；它不是事前推导的服务时间定理，也不能推广到并发、其他 channel/cache 状态或真实硬件。浮点拟合约 10⁻¹⁰ ps 的残差不代表亚皮秒测量精度。[A3 来源](GPU_A3_RESULTS.md)。

## 6. 前端优化与完善方向（建议）

### P0-A：先补测量资格与软件成本分解

**依据：** S6 的插桩扰动、S9 成本分项缺失、A1 的宽区间与顺序效应。首要目标是让目标效应可辨识，而不是再次用累计等待恒等式证明硬件收益。

具体工作：

- 分别记录请求入口、prefill 结束、token ID 可交付、必要输出回传；分开 steady_clock、CUDA/CUPTI 与模拟 Tick，禁止跨时钟直接相减。
- 按加载/初始化、主机调度、后端 CPU 服务、同步、GPU 活动、日志导出、关闭排空分解软件成本；重叠部分报告时间线/关键路径，不把各段耗时直接相加。
- 分离完整核验与低扰动采样；比较同进程/上下文复用及新进程两种协议，固定热身、频率状态记录和交叉顺序。先验证复用不会残留 KV、缓存或后端状态，再用于正式比较。
- 独立校准注入器超调与测量噪声；先冻结目标效应及容许不确定性，再决定样本预算。不能看到区间过宽后放宽原 10% 条件。

**退出条件：** 正式采样前先证明所选剂量可辨识；完整核验与采样模式数学结果/访问身份一致；新样本的区间在冻结标准下判定。精度不足继续报告 inconclusive。只对依赖/token 边界内可合并的短窗口降低采集频次。

### P0-B：把当前功能复验扩为版本绑定的完整矩阵

**依据：** 旧 llama-M6 有长输入/32、64 输出，新基线只重跑 2 输出；旧 4B Capacity 属于另一执行器。

先将三个现有模型的短/长输入、跨 ubatch、跨页行、32/64 输出在新基线上按新批次完整复验；保留原数值判据。增加自然 EOS、0/1 输出、资源不足、取消/超时/失败终止的组件级覆盖清单，区分工具合成测试与真实模型实际触发。历史 S 系列测过某种边界，不自动表示通用模型 runner 支持它。

**退出条件：** 每个矩阵格明确 pass/fail/unsupported，完整输出/字节范围/父子完成/释放检查全部成立；缺格不以其他测试数补足。旧矩阵输入和参照数据需先完成身份映射，不能假定一个旧命令无需调整即可重跑。

### P1-A：扩大真实访问覆盖，先做可审计的增量扩展

**依据：** S8 仅覆盖约 0.000681% 权重，当前 norm/down 选区不能代表整模型卸载。

以现有 profile/能力检查扩到多个层的 norm/down，再到 attention、FFN 的代表性矩阵路径；每次明确实际 kernel、融合、向量宽度、别名、stride、并发 stream 和覆盖边界。对注册字节、唯一触达、累计流量、未建模部分分别出账。权重容量外溢应从真实字节页/lease 接入，不能把多提交几个符号读当成完成外溢。

**退出条件：** 独立范围 oracle 能拒绝缺失/额外/错地址；消费者在最终成功后执行；失败时不消费旧数据；完整 logits/token 合同不变。每扩大一档覆盖都报告新增软件开销和未覆盖比例。算子拆分或融合变化后，重新采集对应计算轨迹，不能沿用旧固定表冒充新执行方式。

### P1-B：从全设备同步门控走向 stream/event 局部依赖

**依据：** 同步 S 路径验证了门控，但主动消除了重叠；实验二/三只在机制层验证了并行收益。

现有 LiveTimingService、服务线程、持久 Session 和异步请求已经存在，不重复建设。优化应落在依赖表达：仅让实际消费者等待对应请求/事件，保持独立 stream 的工作可前进；保留 epoch、借用内存生命周期及 RAW/WAR/WAW。Host 仍负责拆分、调度和重试，不能由前端新增 Device 命令窗口绕过它。

**退出条件：** 先在双分支/汇合的受控图上对拍开始/结束与 makespan，再用真实 GPU 时间线证明重叠确实发生；既有同步实现作为保守参照。以同数值、同覆盖、同资源预算的端到端结果评估收益，不以各请求等待之和代替关键路径。

### P1-C：将预取、容量与版本发布做成统一的可比较策略接口

**依据：** 实验四在容量/预取泛化上失败；历史预取计数通过但没有后台重叠；错误预取可使时间退化。

沿用现有 Capacity/KV 的 allocation、page、pin/lease、dirty、commit 和失败规则，统一需求读/预取/回写/维护的预算与优先级。区分“数据提前到 frame”与“异步 I/O/搬运实际重叠”。逐步加入 lookahead、在途合并、有限队列、需求抢占/取消、缓存污染控制，先比较 no-prefetch 与现有同步预取，再做真正后台路径。

**退出条件：** 固定 GPU frame、额外工作区和 pinned host 预算；统计有效/无用预取、额外读写、阻塞需求和污染退化。保留坏预测、脏页、pin 冲突和失败重试负例；至少在受益和退化两类场景验证策略排序，不能只展示命中数。

### P1-D：用 profiling 证据降低前端软件成本

**依据：** 后端已减少历史扫描/无效通知，但 S9 尚未分离软件成本；后端优化不自动等于前端或硬件加速。

在当前新后端下测量 producer 注册、服务轮询、线程交接、队列分配、日志/审计、页复制和 API 同步的开销及峰值；再选择批处理、缓存元数据、复用对象、减少热路径导出或批量回收。前端已有连续 sector 分组及共享 Session，不能将重复实现这些功能当成新增优化。

**退出条件：** 相同业务输入的地址/内容/完成结果及模拟时刻保持合同；软件 wall time、CPU 占用、峰值内存另行报告。用长运行验证 audit、队列、allocation/版本元数据的增长；不要将 active fragment 上限误称为总内存上限，也不要为省内存丢掉仍需的恢复状态。

### P2：数值资格、敏感性和更广泛适配

- **数值：** 隔离 RMSNorm、RoPE、attention/softmax、矩阵归约和 F16 发布，以相同输入对比独立高精度参照；加入代表性语义错误负控及分离样本。保留分类工程合同，但不称其为形式化全网络界。
- **敏感性：** 补做 S10。用现有多个完整 GPU 样本分别冻结并配对，在预先声明的 H0 参数、覆盖和并发配置上观察策略排序是否稳定。参数扫描只量化假设敏感性；真实 HBF 校准仍需外部测量。
- **泛化：** 三个现有检查点和长上下文先做完整；多序列、量化、MoE、第二框架按独立能力合同逐个加入。不要将历史 4B 自定义 Capacity 成功直接继承为当前 llama.cpp 的 4B 全权重外溢能力。
- **持久化/维护：** 若业务需要再单立续推/崩溃恢复目标；保存模型/KV sequence/调度/时钟身份，核对恢复后行为。Refresh 的 deadline miss 必须成为显式结果，不能以 logits 正确替代可靠性验收。

## 7. 建议执行顺序与验收产物

| 顺序 | 工作包 | 进入条件 | 验收产物 |
| --- | --- | --- | --- |
| R0 | 当前版本完整矩阵、能力/边界清单 | 8ccb1f3 身份及已有回归有效 | 每格结果、数值/访问/释放报告；失败和不支持项保留 |
| R1 | 低扰动测量与软件成本分解 | 数学路径固定，R0 代表案例通过 | 独立注入器测量、先导噪声、冻结正式统计协议、时间线分解 |
| R2 | 逐档扩大权重覆盖 | 独立范围审计、可承受的软件成本 | 覆盖/流量/开销曲线、无效访问和失败停止负控 |
| R3 | 局部依赖、异步容量与预取策略 | R1 测量可分辨、R2 代表路径正确 | 实际重叠证据、相同预算下的收益/退化、独立关键路径审计 |
| R4 | 多轨迹敏感性与进一步泛化 | 策略及接口稳定 | 留出工作负载、跨配置排序、明确的新支持域 |

最先建议投入的是 **R0 与 R1**：前者建立新版本完整功能证据，后者决定后续“优化效果”是否测得出来。R2/R3 的目标与测量方案可并行设计，但不能先用噪声淹没的墙钟样本宣布性能收益。暂不优先再换后端、添加更复杂热模型或一次性接入第二服务框架。

每个新批次都应在执行前固定问题、支持域、对照、输入、验收标准和停止预算；保存源码/二进制/配置身份、原始记录、独立期望及负控。新的工程目标可以单独提出，但不能覆盖 A1 inconclusive、实验四 NOT_PASSED 或旧 B2 失败。
