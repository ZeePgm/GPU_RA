# 第 10 层 Q 权重单次登记的在线介质计时

使用 Qwen3-0.6B F16、原 44-token 输入、两个输出 token 和原生 F16 KV。登记一次 `blk.10.attn_q.weight` 的 GPU 地址和逻辑地址，沿用预填充和解码的原生算子、编译单元、网格、参数和 stream。构建沿用上轮两个编译单元的统一 PTX 探针，运行配置无 CUDA 核名或参数位置。

对后端按需取回的 4 KiB 页，每条实际读取指令先获取完成状态。页上第一次读取发起唯一请求，同阶段的其他读取共享完成。两个阶段分别从空的 GPU 页就绪表启动，EventLab 介质状态接续。主机线程使用现有 `TimingBackend` 处理 Q 的原逻辑范围、一次一个页请求。发布完成后，GPU 等到按首个请求计的模拟截止时间再放行。阶段之间不预取。

对每个原生读取按实际起始字节记录看到成功状态的设备时刻和放行时刻。验收器独立按 2 B 元素计数、动态指令位置和 4 KiB 页回执核对覆盖、模拟时长换算及依赖顺序，检查介质队列排空。比较 Q 投影、完整 logits、token、原生 KV 内容及位置和序列释放。

介质完成回执提供原始 GPU 页地址，原生 load 使用该地址加页内偏移。这样实际执行的指令以介质完成后发布的地址为输入。

权重的动态指令粒度是 8 B 或 4 B，EventLab 的共享服务请求是 4 KiB。模拟介质区间与 GPU 上等待的墙钟区间分别保存。

`build.ps1` 使用 Windows CUDA 13、VS2022 和 Ninja。提交代码 A 并封存 `run.py receipt` 后，通过统一入口直接登记 `run.py measure`，显式使用 `"{config}"`、`"{resource_root}"` 和 `"{run_dir}"`。保留模型、构建收据、两个 PTX 编译清单和原输入身份。
