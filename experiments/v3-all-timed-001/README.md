# Qwen3-0.6B 全权重在线介质计时

模型为冻结的 Qwen3-0.6B F16 GGUF。使用同一份 44-token 输入、两个输出 token、单序列和原生 F16 KV。同一构建分别运行原生组与计时组，保留原生算子和五权重实验已经核对的启动分块。

加载后一次登记 311 个权重地址范围，共 1,503,395,840 有效字节。计时探针由四个原生 ggml CUDA 编译单元生成，按 GPU 原始读地址二分查找区间。框架决定核与调用参数。同一介质状态跨预填充和解码存活。每个阶段的首次触达发布一个按需 4 KiB 页请求，完成回执提供原始 GPU 页基址，到期后原生 load 使用这个地址。EventLab 流式处理在途页，Host 驻留预算为 256 个 64 B 片段，设备单请求保护为 1 秒。

完整后端页数的预期分别是预填充 291,152 页、解码 291,122 页。词嵌入只读真实 token 所选的行，归一化按实际输入列数与注意力头数复读。每个原始 load 更新对应页的放行时间下界、读计数和 2 B 单元覆盖。小于 4 KiB 的权重保留实际 GPU 边界，介质服务按所在逻辑页，尾部填充的 GPU 读数须为零。

两组都按权重记录 311 个计算图消费者、真实输入形状和每个完整算子输出的 SHA-256。最终 logits、KV 字节、位置及序列释放记录直接比较，五类已封存算子引用继续核对。逐页回执、放行时间、覆盖位图、归一化与词嵌入的精确重复次数，以及稀疏的逐权重、逐 PTX 位置动态计数保存在外部运行证据。完整工作区资源扫描、8 GiB 进程内存上限和每页等待保护沿用既有机制。全权重运行预算为每个进程 7,200 秒及 512 MiB 输出。

`build.ps1` 使用 Windows、CUDA 13、VS2022、Ninja。提交代码后以 `run.py receipt` 归档构建身份。使用统一 `experiment.py start` 直接登记 `run.py measure`，冻结模型、prompt、编译清单与历史五类参考清单，显式传入 `{config}`、`{resource_root}`、`{run_dir}`。
