# 五类代表权重的三种接入方式性能比较

状态：**计划已制定，尚未实施、构建或运行。** 实验 ID：`v3-route-perf-five-001`；V3 基线：`9f6eaa71f79d89120b56602d84c99614ef22839e`。本次提交是计划 P，不能作为运行源码提交 A 或结果报告 B。

预算修订：保留 44-token 提示，生成量由 8 缩至 4 token。模型每次接入消费者由 40 减至 20，减少一半的逐步大矩阵接入工作；初始化、逐权重矩阵及三次独立重复不变，因此不将总执行时间称为减半。总执行预算由 10h 收紧至 7.5h，仍需预跑确认可行性。已有 15-token 短提示只减少 prefill 的激活计算及少量嵌入行，不减少每步矩阵权重读取；本轮优先减少生成步数。

## 1. 比较目标与边界

比较 symbolic、PTX、CUDA 完成同一外部任务的实际耗时，允许三者保留不同的数据工作、实现和分块策略；所有内在开销均计入结果。symbolic 不返回 payload、PTX/CUDA 读取并发布 payload 的差异属于实现本身，不因此拆分排名。请求数、处理字节和模拟时钟用于解释结果，不作为性能分母或修正系数。

本轮回答两件事：单个代表权重连同原始 GPU 消费算子的延迟；仅将这五个权重接入时，完整模型的 TTFT、TPOT 和生成耗时。五权重模型中另外 306 个权重走原生路径，KV 走原生路径。结果适用范围限定为本模型、GPU、输入、上下文及当前实现配置，不外推所有权重或所有序列长度。

| 方式 | 正常分块 | u16 回退分块 | 保留项 |
|---|---:|---:|---|
| symbolic | 262144 B（256 KiB） | 32768 B | 当前符号请求与门控实现 |
| PTX | 32768 B（32 KiB） | 4096 B | 当前 PTX 改写、读回与发布实现 |
| CUDA | 262144 B（256 KiB） | 32768 B | 当前 helper/读回/发布实现；现有 8 blocks × 256 threads |

记录实际选择的块型、尾块与回退原因，不强制三者使用相同块大小，不在本轮调参或重新选择最优分块。接入实现修改仅限 `joint/source`，历史冻结源码及验收器保持原样。

## 2. 测试矩阵

P 表示原始 44-token 提示的 prefill 消费者；D 表示第一轮单 token decode 消费者。使用原生参考运行捕获的真实激活值、shape、stride 和 token 索引，不能用随机输入替代。张量维度沿用 GGML 顺序。

| 权重 | 类型 / 物理大小 | 原始消费者 | P / D 工作量 | 每进程首次 + 重复次数 |
|---|---|---|---|---:|
| `blk.10.ffn_norm.weight` | F32 `[1024]` / 4 KiB | MUL，权重 src1 | 激活 `[1024,44]` / `[1024,1]`；输入已完成 RMS 归一化 | 1 + 5 |
| `blk.10.attn_q.weight` | F16 `[1024,2048]` / 4 MiB | MUL_MAT，权重 src0 | 输出 `[2048,44]` / `[2048,1]` | 1 + 5 |
| `blk.10.ffn_down.weight` | F16 `[3072,1024]` / 6 MiB | MUL_MAT，权重 src0 | 输出 `[1024,44]` / `[1024,1]` | 1 + 5 |
| `token_embd.weight` | F16 `[1024,151936]` / 296.75 MiB | GET_ROWS，权重 src0 | 44 行 / 1 行，每行 2048 B；保留索引顺序和重复行 | 1 + 5 |
| `output.weight` | F16 `[1024,151936]` / 296.75 MiB | MUL_MAT，权重 src0 | P、D 都是输入 `[1024,1]`、输出 `[151936,1]`；整张权重参与投影 | 1 + 1 |

输出投影 P/D 各自取真实激活，不能把 P 强行扩成 44 列；嵌入不能改为全表扫描。五个权重的物理字节合计 632819712 B。

**A 层：逐权重。** 5 权重 × 2 场景 × 3 方式 = **30 格**；每格 3 个独立新进程，共 **90 进程**。每进程先测 1 次首次调用，随后按上表测重复调用。共 90 个首次值 + 378 个重复值 = **468 个任务延迟值**。输出矩阵成本高，固定只重复 1 次；不得将它解释为已证明达到稳态。

**B 层：完整模型。** 只接入上述五权重，44-token 提示、生成 4 token、原生 KV；3 方式 × 3 独立新进程 = **9 进程 / 9 条序列**。每进程只生成一次，没有额外模型预热序列。记录每步 logits、token 与 KV 结果，预期 4 × 5 = 20 个所选权重消费者。不同提示、长序列、modeled-KV 和分块优化留待后续实验。

正式矩阵合计 **99 个独立进程**。原生参考运行用于输入捕获与正确性，不列为第四种接入方式的性能排名。

## 3. 顺序、重复与统计

逐权重固定场景顺序：上表自上而下，每个权重 P 后 D。每轮遍历十个场景；每个场景内方式顺序采用三轮轮换：第 1 轮 symbolic→PTX→CUDA，第 2 轮 PTX→CUDA→symbolic，第 3 轮 CUDA→symbolic→PTX。模型层也按此三轮顺序。完整顺序见 `matrix.json`。

所有 GPU 进程串行；沿用原资源守卫，扫描完整 `E:\v1_update`，不与其他科学实验并行。记录 GPU、驱动、CUDA、CPU、环境及运行前后的温度/时钟状态；不清空驱动/JIT 缓存，不将“进程首次”称为“GPU 冷缓存”。硬件设置变化或守卫拒绝时保留记录并暂停，不能忽略后继续混合样本。

逐权重的独立统计单位是进程：先计算每进程重复调用的算术均值，再报告三个进程均值的中位数及 min/max，附全部单次值。首次延迟、初始化和首次结果耗时分别汇总。模型层按三个进程分别汇总 TTFT、TPOT 及生成耗时，再报告中位数及 min/max。

方式 X 相对 Y 的加速比为 `median(L_Y) / median(L_X)`，TTFT/TPOT 同理；大于 1 表示 X 更快。不给不同权重任意加权产生唯一总排名。N=3 只作描述性比较，不报告 p95、显著性或窄置信区间。若三轮排序不一致或区间明显交叠，报告排序不稳定；不根据已见结果追加重复或删除慢样本。失败、中断和预算停止均列入总账，不补成“全通过”的三次。

## 4. 指标与计时边界

主计时用同一进程内的单调 CPU 墙钟，统一输出 ns 和 ms；GPU 完成事件用于确认完成，CPU 必须等到该完成被观察到。模拟时钟和 CUDA event 时间只能作分项诊断，不替换或从主耗时中扣除。

| 指标 | 起点与终点 | 定义 / 包含项 |
|---|---|---|
| 任务完成延迟 L | 输入已在 GPU 就绪后，进入接入路径前 `s`；原生消费者的 GPU 输出确实完成且被 CPU 观察到 `e` | `L=e-s`；包含请求、等待、复制/发布、接入及原生 MUL/MUL_MAT/GET_ROWS、必要同步，以及调用中发生的分配/JIT |
| 初始化 T_init | `u0` 在首次 CUDA、模型、服务、JIT 或注册工作之前；`u_ready` 在所需权重、输入 GPU 缓冲、服务和上下文就绪后 | `T_init=u_ready-u0`；通用 CLI 和 CPU fixture 元信息解析可在 u0 前，方式特有准备不能前移 |
| 首次调用 L_first | 第一次任务的 `s_first` 到 `e_first` | 包含首次调用的惰性工作，单列且不混入重复均值 |
| 首次结果 T_first | u0 到第一个任务输出完成 `e_first` | `T_first=e_first-u0`；保留全部时间戳，不强行假定等于 T_init+L_first |
| TTFT | 模型已初始化、提示已分词，进入 prefill 前 t0；第一个生成 token ID 可交给调用者时 t1 | `TTFT=t1-t0`，包含 prefill 与首 token 所需采样/传输 |
| TPOT | 第一个到第四个 token 可交付的时刻 t1、t4 | `TPOT=(t4-t1)/3`；同时保留三个逐 token 间隔；仅代表短 decode，不代表长序列稳态 |
| decode 吞吐 | 同上 | 若时间以 ms 表示，`3000/(t4-t1)` token/s |
| 生成耗时 | t0 到 t4 | `T_gen=t4-t0`；初始化另列 |

L 的终点不能取“请求提交”“镜像就绪”或“门控放行”。第一次调用前排空初始化 GPU 工作；连续重复调用使用同样的冻结输入和各自预分配输出缓冲。先完成全部计时调用，再批量验证和写文件，避免校验 D2H 或落盘插入相邻调用。保留实现本来必需的流间依赖、等待及审计队列排空，不做人工时间扣除。

模型每个 t_i 位于 token 已可交付、审计写盘之前；模型运行所需的采样和数据传输照常计入。完整 logits/KV 归档和实验专用校验在 t4 后执行。CPU 进程总耗时、CPU 时间、Host 峰值内存为辅助成本；GPU 报告各阶段内存快照和受控分配上界，不把离散快照称为连续峰值。父进程总墙钟另记，覆盖 OS 启动及 DLL 装载等 u0 之前的成本。
